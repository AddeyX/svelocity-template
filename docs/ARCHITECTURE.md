# Architecture

**Purpose.** Map of the template. Depth lives in the subsystem files.

**Covers.** The two Workers, the Convex backend, and the invariants that hold for the demo.

**Does not cover.** Product copy (`PRODUCT.md`, `VISION.md`) and color (`DESIGN.md`).

```text
Browser
  → apps/web (SvelteKit, Worker stack-web) → Convex
Visitor
  → apps/site (SvelteKit, Worker stack-site) → waitlist.join
Desktop
  → apps/desktop (SvelteKit hash router, Electron) → Convex
Phone
  → apps/mobile (SvelteKit static, Capacitor) → Convex
```

## Invariants

1. Convex is the source of truth for notes and the waitlist.
2. The URL owns navigation.
3. Every public Convex function authenticates first. `waitlist.join` is the named exception.
4. A live `authSessions` row is required. A JWT alone is not enough.
5. Note text is 1–200 characters. A list page is at most 50 notes.
6. `items.remove` returns `{ changed: true }` or throws. Missing and foreign notes are `NOT_FOUND`.
7. Generated Convex files are committed. `worker-configuration.d.ts` is generated by `pnpm gen` and gitignored.
8. Validate never deploys. Deploy publishes Convex, then `stack-web`, then `stack-site`.
9. Electron APIs stay in `apps/desktop`. Capacitor APIs stay in `apps/mobile`.
